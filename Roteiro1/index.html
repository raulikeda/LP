    Roteiro 2 - v1.0

    Entrega: 28/Aug/2025 às 07h15

    Objetivos

    1. Reestruturar o compilador para o modelo visto em aula.
    2. Implementar a separação de fases.

    Requisitos do Roteiro

    Você irá implementar a análise léxica e a análise sintática através de duas classes diferentes: Lexer e Parser.

    A análise léxica ocorrerá na classe Lexer. Ela armazenará o código de entrada no atributo source e realizará a tokenização através do método selectNext(). O metódo irá preencher o atributo next com um objeto do tipo Token.

    Haverá 4 tokens diferentes disponíveis:

    • (INT, value) - que representa o valor de um número
    • (PLUS, '+') - que representa o símbolo +
    • (MINUS, '-') - que representa o símbolo -
    • (EOF, '') - que representa o final da string de entrada

    O método selectNext() irá quebrar o código fonte sob demanda, sempre analisando um caractere específico representado pelo índice position.

    Ao achar um símbolo de interesse, irá parar e atualizar o atributo next com o token correspondente. Ao ser chamada novamente, continuará a análise de onde parou (position atual). O método deverá ignorar os espaços em branco.

    Um possível algoritmo seria: 

      Seja caractere atual definido pelo índice position atual
  Enquanto for um espaço em branco
    avance o índice position e atualize o caractere
  Se o índice position é maior que o tamanho de entrada
    next será o token (EOF,'')
  Se o caractere é igual a '+'
    next será o token (PLUS,'+')
  Se o caractere é igual a '-'
    next será o token (MINUS,'-')
  Se o caractere for um dígito
    salve o dígito e avance um caractere
    Enquanto o caractere for um dígito
      salve o dígito concatenando com o anterior
    next será o token (INT, número convertido)

    A classe Parser, responsável pela análise sintática, irá requisitar os tokens para o Lexer e verificar se a ordem de extração está condizente com o Diagrama Sintático.

    O diagrama apresentado em aula será representado pelo método estático parseExpression(). Convertendo o Diagrama, um possível algoritmo para a função é:

      Se o next token não é um número, ERRO
  Resultado recebe o valor do next token INT
  Posicione no próximo token
  Enquanto o next token for PLUS ou MINUS
    Posicione no próximo token
    Se o next token não é um número, ERRO
    Atualize o resultado conforme a operação indicada
    Posicione no próximo token
  retorne o resultado

    A classe Parser deverá conter um método estático run(), que servirá de ponto de entrada para iniciar a análise. Atualmente o método irá criar um objeto Lexer e realizar a chamada do método parseExpression(). Ao retornar com o resultado, deve-se verificar se o next token é um EOF. Ao final, retornar o resultado para a impressão na main.

    Atenção

    A especificação acima utiliza a formatação camelCase, usualmente utilizada em Java/JavaScript. Se você utiliza o Python, converter para o formato snake_case para soar mais idiomático (PEP8).

    Sobre as mensagens de erro

    Coloquem mensagens de erro que façam sentido. Coloquem também a fonte do erro. Isso irá facilitar a depuração no futuro.

    Por exemplo: [Parser] Unexpected token PLUS ou [Lexer] Invalid Symbol $

    Sobre Classes e Objetos

    Caso você não recorde, segue uma breve revisão de OOP (Object Oriented Programming) em Python.

    Para criar uma classe em Python, você utiliza a seguinte estrutura:

    class MyClass:
    def __init__(self, a, b):
        self.a = a
        self.b = b
    def do_something(self, x):
        return self.a + self.b + x

# Criando um objeto do tipo MyClass
obj = MyClass(2, 3)
# Imprime o resultado da chamada da função (método)
print(obj.do_something(4))

    A classe acima possui 2 atributos (a e b) e dois métodos (__init__() e do_something()). __init__ é conhecido como construtor e chamado no momento da criação do objeto (ou instância).

    Herança é uma operação cuja uma classe filha herda todos os atributos e métodos da classe pai.

    class DerivedClass(MyClass):
    # O construtor (__init__()) é herdado de MyClass

    def do_otherthing(self, y):
        # do_something foi herdado da classe MyClass
        return self.do_something(y)

    A classe filha pode também sobrescrever (override) o código original ou criar novos atributos e métodos.

    class DerivedClass(MyClass):
    def __init__(self, a, b, c):
      # Chama o construtor de MyClass
      super().__init__(a, b)
      # Cria um novo atributo
      self.c = c

    def do_something(self):
        # do_something será substituído
        return self.a + self.b + self.c

    Quando iniciado com o prefixo self, diz-se que o atributo é dinâmico e pertence exclusivamente ao OBJETO da classe.

    obj1 = MyClass(1, 2)
print(obj1.a) # Imprime 1
obj2 = MyClass(3, 4)
print(obj2.a) # Imprime 3

    O mesmo se aplica aos métodos cujo o primeiro argumento é o self.

    Em oposição, atributos e métodos são estáticos quando eles são compartilhados entre todas as instâncias da classe.

    class OtherClass:
    z = 0 # atributo estático (sem self)
    # Não há construtor definido
    # Método estático (sem argumento self)
    def do_other_action(w):
        # Note o uso do atributo estático
        return OtherClass.z + w

# Note que NÃO há criação de objetos
print(OtherClass.z) # Imprime 0
OtherClass.z = 7
print(OtherClass.z) # Imprime 7
print(OtherClass.do_other_action(2)) # Imprime 9

    A class acima funciona como que um módulo, agrupando funções e variáveis com escopo mais amplo. Também notar que:

    obj1 = OtherClass()
print(obj1.z) # Imprime 7 (último valor de z)
obj1.z = 3

obj2 = OtherClass()
print(obj2.z) # Imprime ???

    Como explicado, atributos estáticos são compartilhados entre todos e atributos dinâmicos são específicos da instância. Essa implementação pode ser úteis em alguns casos, principalmente em arquiteturas singletons.

    Um último conceito importante na disciplina são as Classes Abstratas. Apesar do Python não implementar essa feature, significa simplesmente de que não deveria ser possível construir objetos da classe, apenas herdá-la.

    Apesar do Python não implementar OOP plenamente, há outras características que valem a pena uma profunda revisão para relembrar os conceitos fundamentais, como properties, overloading, interfaces, etc.

    Tarefas:

    1. Colocar o Diagrama Sintático no README do GitHub.
    2. Criar uma Classe Token com 2 atributos:
      • kind: string. É o tipo do token
      • value: integer | string. É o valor do token
    3. Criar uma Classe Lexer com 3 atributos e 1 método:
      • source: string. É o código-fonte que será tokenizado
      • position: integer. É a posição atual que o Lexer está separando
      • next: Token. É o último token separado
      • selectNext(): lê o próximo token e atualiza o atributo next
    4. Criar uma Classe Parser com 1 atributo e 2 métodos (estáticos):
      • lex: Lexer. Objeto da classe que irá ler o código fonte e alimentar o Parser.
      • parseExpression(): int: consome os tokens do Lexer e analisa se a sintaxe está aderente à gramática proposta. retorna o resultado numérico da expressão analisada.
      • run(code: string): int: recebe o código fonte como argumento, inicializa um objeto Lexer em lex, posiciona no primeiro token e retorna o resultado do parseExpression(). Ao final verificar se terminou de consumir toda a cadeia (o token deve ser EOF).
    5. O main() do compilador deve chamar o método Parser.run() e imprimir o retorno do método.
