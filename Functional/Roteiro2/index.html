    Roteiro 2 (Functional) - v1.0

    Entrega: 03/Mar/2026 às 07h15

    Objetivos

    1. Reestruturar o compilador para o modelo visto em aula.
    2. Implementar a separação de fases.

    Requisitos do Roteiro

    Você irá implementar a análise léxica e a análise sintática através de dois tipos diferentes: Lexer e Parser.

    Lexer será um alias (String, Int), representando o código fonte de entrada no compilador e a posição do caractere analisado.

    Já o tipo Token consiste em uma construção:

    data Token
  = PLUS
  | MINUS
  | INT Int
  | EOF

    Onde haverá diferentes disponíveis:

    • INT value - que representa o valor de um número
    • PLUS - que representa o símbolo +
    • MINUS - que representa o símbolo -
    • EOF - que representa o final da string de entrada

    A análise léxica ocorrerá através de uma função selectNext :: Lexer -> (Lexer, Token). Ela irá quebrar o código fonte sob demanda, sempre analisando um caractere específico representado pelo índice de posição.

    Ao achar um símbolo de interesse, irá parar e retornar o Token correspondente. Como não há estados, a função retorna o próprio código de entrada e a posição atualizada.

    Um possível algoritmo seria: 

      Pule os espaços atualizando a posição
  Se posição for maior que o tamanho da string, Token será EOF
  Senão
    Se o char for '+', Token será Plus
    Se o char for '-', Token será Minus
    Se o char for dígito, selecione todos os dígitos subsequentes. Token será Int com o valor numérico achado.
    Caso contrário, será um erro léxico

    Você pode usar as funções isDigit e isSpace como suporte. Você também pode controlar a recursão usando takeWhile/span e drop.

    O tipo Parser será uma construção:

    type Parser a = (Lexer, Token) -> (a, (Lexer, Token))

    E todas as funções da análise sintática seguirão essa construção. As funções receberão um Lexer e um Token e devolverão um resultado, seguido do Lexer atualizado e o próximo Token já selecionado. As funções seguirão o padrão exibido no Diagrama Sintático:

    Convertendo o Diagrama, um possível algoritmo para a função parseExpression é:

    função parseExpression :: Parser Int
  Se Token é Int, chame uma função auxiliar com o valor e o próximo Token
  Senão erro sintático
  função auxiliar:
    Se Token é Plus, some o resultado com parseExpression usando próximo Token
    Se Token é Minus, subtraia o resultado com parseExpression usando próximo Token
    Senão retorne.

    Adicionalmente, criar uma função run, que servirá de ponto de entrada para iniciar a análise. A função deverá chamar parseExpression posicionando no primeiro Token. Ao retornar com o resultado, deve-se verificar se o Token é um EOF. Ao final, retornar o resultado para a impressão na main.

    É esperado algo como:

    run :: String -> Int
run code =
    let (val, (_, tok)) = parseExpression (selectNext (code, 0))
    in case tok of
        EOF -> val
        _   -> error "[Parser] Unexpected tokens after expression"

    Atenção

    A especificação acima utiliza a formatação camelCase, usualmente utilizada em Haskell. Se você utiliza o OCaml ou F#, converter para o formato snake_case ou PascalCasepara soar mais idiomático.

    Sobre as mensagens de erro

    Coloquem mensagens de erro que façam sentido. Coloquem também a fonte do erro. Isso irá facilitar a depuração no futuro.

    Atualmente teremos erros com os prefixos:

    • [Parser] para erros disparados na classe Parser
    • [Lexer] para erros disparados na classe Lexer

    Por exemplo: [Parser] Unexpected token PLUS ou [Lexer] Invalid Symbol $

    Sobre Tipos e Construções

    Linguagens Funcionais não trabalham com o conceito de Classes e Objetos. Na realidade não trabalham com o conceito de variável como uma linguagem procedural. Existem binding imutáveis que atribuem localmente um label para um contexto.

    Portanto o conceito de modelagem é um pouco diferente do usualmente utilizado em Linguagens Orientadas a Objetos (OOP). Em linguagens funcionais trabalha-se com Tipos ao invés de classes. E a construção desses tipos podem ocorrer via intersecção (record ou tuplas) ou união, ou ambos.

    Por exemplo, Token seria uma Classe com dois atributos: type: String e value: Int | String. Ao transpormos para o mundo funcional, Token vira um tipo e o type é definido pelo seu construtor (NT: não confundir construtor de tipos com construtor de objetos de uma classe, são ideias parecidas, mas não é a mesma coisa).

    Como temos 4 tipos diferentes de token: [INT, PLUS, MINUS, EOF], isso se torna o tipo Token:

    data Token
  = PLUS
  | MINUS
  | INT Int
  | EOF

    Como PLUS, MINUS e EOF não precisam armazenar um value, não é necessário passar valores na construção. Para criar uma variável do tipo Token, basta construir:

    let v = PLUS -- v é um Token PLUS
let w = INT 2 -- w é um Token INT com o valor 2

    E isso facilita o uso via pattern matching:

    case v of
   PLUS -> ... -- Se v for um Token PLUS
   (INT n) -> ... -- Se v for um Token INT, e n será o valor de fato

    Também é possível construir um tipo que concatena dois tipos distintos (type alias):

    type Lexer = (String, Int)

    Isso indica que tudo que for do tipo Lexer, será constituído de uma tupla de 2 dimensões (ou dupla), uma String e uma Int. E isso ajuda na hora de realizar o pattern matching:

    selectNext :: Lexer -> (Lexer, Token)
selectNext (src, pos) = 
  -- Lexer será decomposto em Str, Int e os valores assimilados em src e pos
  ...

    Sobre Loops

    Não há loops no sentido procedural (while, for, repeat, goto, etc). É preciso realizar recursões para realizar laços. Contudo muito cuidado para deixar explícito pelo menos um caso base para não ocorrer loop infinito. Outra forma de realizar laços é utilizando Map ou Fold.

    É muito comum o uso de funções auxiliares para executar loops via recursão. É o caso do parseExpression do roteiro.

    parseStatement :: Parser Int
parseStatement (lex, token) = 
    case token of
      (INT n) -> aux n (selectNext lex)
      _ -> error "[Parser] Expected token INT"
  where
    aux acc (lex, token) =
       let (lex', token') = selectNext lex
       in case (token, token') of
            PLUS, (INT n) -> aux (acc + n) lex' 
            ...

    Atenção: Ao realizar fold, tradicionalmente a linguagem realiza o fold à esquerda, o que fará com que a execução seja invertida. Caso deseje iterar sem inversão, utilize foldr ou flip. Isso também pode acontecer com recursões, dependendo da forma com que ela é construída.

    Atenção 2: Haskell utiliza o conceito de lazy evaluation, ou seja, só executa as expressões quando realmente precisa. Isso pode apresentar efeitos colaterais indesejados. Às vezes é preciso forçar a execução de trechos de código utilizando seq.

    Sobre Monads e Pureza

    Tente ao máximo possível deixar as funções puras. main naturalmente será IO () porque precisa receber valores e imprimir o resultado. Evite ao máximo o uso de monads como Either ou Maybe, prefira construções de tipos.

    Vai chegar um momento em um roteiro posterior que será inevitável o uso de monads (list, state, IO, etc), mas por enquanto, ainda não será necessário. Lembre-se que: uma vez dentro do monad, nunca mais (deveria estar) fora do monad, a função que é levada (lift) para dentro do mundo monádico.

    Tarefas:

    1. Colocar o Diagrama Sintático no README do GitHub.
    2. Criar um tipo Token
    3. Criar um tipo Lexer
    4. Criar uma função selectNext: recebe o código de entrada e a posição e retorna o Token correspondente.
    5. Criar um tipo Parser
    6. Criar a função parseExpression: consome os tokens do Lexer e analisa se a sintaxe está aderente à gramática proposta. retorna o resultado numérico da expressão analisada.
    7. Criar a função run: recebe o código fonte como argumento, posiciona no primeiro token e retorna o resultado do parseExpression. Ao final verificar se terminou de consumir toda a cadeia (o token deve ser EOF).
    8. O main do compilador deve chamar a função run e imprimir o retorno da função.

      >> 2 ^ 3
