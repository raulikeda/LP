    Sobre Programação Funcional

    Se você está lendo essa parte do site de roteiros, você está interessado ou quer fazer o projeto em uma linguagem majoritariamente funcional. Para isso é preciso assimiliar um conjuntos de técnicas e conceitos que vão além de uma mera tradução de linguagem procedural para funcional.

    Vamos ser bem práticos e deixar para depois os conceitos mais tradicionais como:

    • Funções como cidadãos de primeira classe
    • Partial Application, Curry, Closure, HOF, TCO
    • Pureza e monads
    • etc

    A medida que vai avançando nos roteiros, esses conceitos vão ficando mais claros.

    Para início, precisao apenas entender parte da filosofia funcional e aplicação no projeto. Lembrando que programar em estilo funcional está pouco ligado à linguagem utilizada e mais na disciplina do programador. É possível programar quasi-proceduralmente em linguagens funcionais e quasi-funcional em linguagens multiparadigmas, como Python.

    Vamos focar em 3 aspectos principais por enquanto:

    • Tipos e a ausência de estados
    • Ausência de instruções como if e for/while
    • Imutabilidade

    Sobre Tipos e Construções

    Linguagens Funcionais não trabalham com o conceito de Classes e Objetos. Na realidade não trabalham com o conceito de variável como uma linguagem procedural. Existem binding imutáveis que atribuem localmente um label para um contexto. Quando diz que: let x = 3, x realmente é igual a 3 e não que x "vale" 3. E x sempre será 3 nesse contexto (imutabilidade).

    Portanto o conceito de modelagem é um pouco diferente do usualmente utilizado em Linguagens Orientadas a Objetos (OOP). Em linguagens funcionais trabalha-se com Tipos ao invés de classes. E a construção desses tipos podem ocorrer via intersecção (record ou tuplas) ou união, ou ambos.

    Por exemplo, em uma linguagem procedural Token seria uma Classe com dois atributos: type: String e value: Int | String. Ao transpormos para o mundo funcional, Token vira um tipo e o type é definido pelo seu construtor (NT: não confundir construtor de tipos com construtor de objetos de uma classe, são ideias parecidas, mas não é a mesma coisa).

    Como temos 4 tipos diferentes de token: [INT, PLUS, MINUS, EOF], isso se torna o tipo Token em Haskell:

    data Token
  = PLUS
  | MINUS
  | INT Int
  | EOF

    Como PLUS, MINUS e EOF não precisam armazenar um value, não é necessário passar valores na construção. Para criar uma variável do tipo Token, basta construir:

    let v = PLUS -- v é um Token PLUS
let w = INT 2 -- w é um Token INT com o valor 2

    E isso facilita o uso via pattern matching:

    case v of
   PLUS -> ... -- Se v for um Token PLUS
   (INT n) -> ... -- Se v for um Token INT, e n será o valor de fato

    Também é possível construir um tipo que concatena dois tipos distintos (type alias):

    type Lexer = (String, Int)

    Isso indica que tudo que for do tipo Lexer, será constituído de uma tupla de 2 dimensões (ou dupla), uma String e uma Int. E isso ajuda na hora de realizar o pattern matching:

    selectNext :: Lexer -> (Lexer, Token)
selectNext (src, pos) = 
  -- Lexer será decomposto em Str, Int e os valores assimilados em src e pos
  ...

    Sobre Loops e condicionais

    Não há loops no sentido procedural (while, for, repeat, goto, etc). É preciso realizar recursões para realizar laços. Contudo muito cuidado para deixar explícito pelo menos um caso base para não ocorrer loop infinito. Outra forma de realizar laços é utilizando Map ou Fold.

    É muito comum o uso de funções auxiliares para executar loops via recursão. É o caso do parseExpression do roteiro.

    parseStatement :: Parser Int
parseStatement (lex, token) = 
    case token of
      (INT n) -> aux n (selectNext lex)
      _ -> error "[Parser] Expected token INT"
  where
    aux acc (lex, token) = -- aqui aux é uma função declarada dentro de outra função
       let (lex', token') = selectNext lex
       in case (token, token') of
            PLUS, (INT n) -> aux (acc + n) lex' 
            ...

    Atenção: Ao realizar fold, tradicionalmente a linguagem realiza o fold à esquerda, o que fará com que a execução seja invertida. Caso deseje iterar sem inversão, utilize foldr ou flip. Isso também pode acontecer com recursões, dependendo da forma com que ela é construída.

    Atenção 2: Haskell utiliza o conceito de lazy evaluation, ou seja, só executa as expressões quando realmente precisa. Isso pode apresentar efeitos colaterais indesejados. Às vezes é preciso forçar a execução de trechos de código utilizando seq.

    Já o condicional deve ser feito tradicionalmente via pattern matching ou if inline (conhecido como if expression ou operador ternário).

    Imutabilidade

    Por padrão, em uma linguagem funcional, e algumas procedurais, as variáveis são imutáveis. Isso significa que além de fortemente tipado, ela não pode ter o seu valor modificado. Evite ao máximo adicionar a cláusula que torna as variáveis mutáveis. Se a linguagem for naturalmente mutável, cabe ao programador se policiar para não reutilizar as variáveis.

    Sobre Monads e Pureza

    Monad é um conceito simples, mas ao mesmo tempo pode levar para um buraco bem profundo a medida em que cava mais. A ideia principal é encapsular um valor em um determinado contexto. Esse contexto pode representar várias coisas: um possível erro, uma operação de entrada e saída, um estado, uma lista de possibilidades, entre outras.

    O interessante é que, mesmo depois de colocar o valor nesse contexto, ainda conseguimos continuar aplicando operações sobre ele. Por exemplo, se temos um valor ou um erro, podemos continuar encadeando funções sem precisar verificar manualmente, a cada passo, se o resultado anterior foi um sucesso ou não.

    O monad não precisa retirar o valor de dentro desse contexto para continuar trabalhando. Em vez disso, as funções são adaptadas para trabalhar com valores que estão nesse "mundo". É daí que vem uma frase bastante útil para criar uma intuição inicial: Uma vez dentro do monad, nunca mais fora do monad.

    Não leve a frase literalmente, mas ela é uma boa regra mental. Se uma sequência de operações começou retornando o monad Result, por exemplo, normalmente é mais simples continuar retornando Result até chegar à fronteira do programa, onde finalmente decidimos o que fazer com o sucesso ou com o erro.

    Essas ideias possuem uma fundamentação matemática bastante interessante. Se quiser, o buraco é realmente profundo. Mas não é necessário conhecer toda essa matemática para começar a usar monads.

    Portanto, a recomendação é:

    Tente ao máximo manter suas funções puras, isto é, dadas as mesmas entradas, elas sempre produzem as mesmas saídas. Algumas partes do programa inevitavelmente terão efeitos colaterais. Em Haskell, por exemplo, o main normalmente possui tipo IO (), justamente porque interage com o mundo externo vai print ou input. Para erros, idealmente podemos utilizar algo como Either ou Result, mas, em um primeiro momento, mantenha as coisas simples e use exceções quando isso deixar o código mais fácil de entender.

    Aprender programação funcional é um pouco como aprender a andar de bicicleta. Algumas ideias parecem estranhas até você começar a utilizá-las. Depois de algum tempo, você percebe que está usando composição, tipos algébricos e até monads sem pensar muito sobre isso.

    Em roteiros posteriores chegará um momento em que encontraremos naturalmente estruturas como List, State, IO, Result e outras. Algumas delas podem ser vistas como monads e veremos que existe um padrão comum entre elas.

    Por enquanto, guarde apenas a intuição: quando colocamos um valor em determinado contexto, queremos continuar compondo operações sem precisar desmontar e reconstruir esse contexto a cada passo.

    Haskell torna essa ideia especialmente explícita por possuir suporte direto, através de abstrações como a typeclass Monad e da notação do. Mas isso não significa que a mesma ideia não possa ser aplicada em linguagens multiparadigmas como Python ou JavaScript. Podemos construir as mesmas abstrações e obter boa parte dos mesmos benefícios.

    Ignore, por enquanto, os puristas intransigentes. Se te perguntarem: "O que é um monad?" reponda: um burrito e ria.
