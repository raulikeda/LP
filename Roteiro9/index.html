    Roteiro 9 - v2.3

    Entrega: 09/Nov/2025 às 07h15

    Objetivos

    1. Implementar Declarações de Funções
    2. Escopo de variáveis

    Exemplo de sintaxe:

    var b int = 5 // Variável Global

func soma(x int, y int) int {
  var a int // Variável Local
  a = x + y 
  Println(a) // Imprime 7
  return a
}

func main()  {
  var a int
  {
    var b int
    a = 3
    b = soma(a, 4)
    Println(b) // Imprime 7
  }
  Println(a) // Imprime 3
  Println(b) // Imprime 5
}

    Funções

    Como exemplificado acima, a linguagem permite declarar funções simples e com declaração de tipo. Todas as funções a princípio possuem visibilidade pública e podem ser usadas em outras Funções. Não será possível declarar uma função dentro de uma função.

    • Na linguagem se a função não declarar um tipo, não pode dar return. A função main é obrigatória.

    Lexer

    • Adicionar a palavra reservada func: token FUNC
    • Adicionar a palavra reservada return: token RETURN
    • Adicionar o símbolo ,: token COMMA

    AST - Parte I

    • Adicionar o Node FuncDec
    • Adicionar o Node FuncCall
    • Adicionar o Node Return

    Deixar a implementação vazia por enquanto

    Parser

    • Adicionar o parse_func_declaration(). Vai gerar um nó FuncDec
    • FuncDec terá n+2 filhos. Onde n é a quantidade de argumentos (nós tipo VarDec). O primeiro filho será um Identifier e o último filho será um Block. O tipo de retorno da função entrará no valor do próprio FuncDec
    • Adicionar a chamada do parse_func_declaration() no parse_program(). Precisa pensar um pouco como decidir o caminho correto.
    • No parse_statement():
    • Adicionar a chamada de função após um token IDEN. Se houver um OPEN_PAR é chamada de função. Se houver um ASSIGN é uma atribuição. Vai gerar um nó FuncCall
    • FuncCall terá n filhos, onde n é a quantidade de argumentos na chamada. São expressões.
    • Adicionar o tratamento do RETURN. Vai gerar um nó Return
      • Return terá apenas 1 filho. Será uma expressão.
    • No parse_factor():
    • Adicionar a chama de função (igual ao anterior)

    SymbolTable

    • Modificar o construtor adicionando um novo argumento para um novo atributo parent. O valor inicial é None
    • Modificar os métodos getter e setter para realizar buscas recursivas
    • Não precisa modificar o create_variable

    Node Return

    • Retorna o valor do evaluate() do próprio filho.

    Obs: return é teoricamente um statement, mas ele precisa de um tratamento adicional no Block

    Node Block

    • Precisa retornar o valor no Block quando o filho executado for um Return

    Com a possibilidade de haver Block dentro de outro Block, precisa tratar o escopo adequadamente:

    • Precisa criar uma nova SymbolTable encadeada quando o filho a ser executado for um outro Block. Utilizar a nova SymbolTable no evaluate do filho (Block)

    • Será necessário também ajustes nos nós If e While para retornar valores se o Block retornar valor.

    Node FuncDec

    FuncDec é um nó muito simples. O evaluate() apenas adiciona na SymbolTable uma "variável" que guarda a sua própria referência como valor. Armazenar também o tipo do retorno e um novo atributo na classe Variable para indicar que trata-se de uma função. Em função da sintaxe, a declaração ocorrerá sempre na primeira SymbolTable.

    Precisa também alterar o nó VarDec, para ajustar esse atributo adicional.

    Node FuncCall

    Aqui é onde a execução realmente acontece. Como uma função pode ser chamada diversas vezes com parâmetros diferentes, precisa recuperar a assinatura da função e montar a chamada. Segue a lista de tarefas:

    • Verifique se a função foi declarada
    • Recupere a referência do nó FuncDec que contém a estrutura da função
    • Verifique se o número de argumentos passados bate com a declaração
    • Crie uma nova SymbolTable
    • Simultaneamente:
    • Declare os argumentos na nova SymbolTable
    • Realize o evaluate() dos argumentos passados e preencha na SymbolTable
    • Capture o return, se houver, e verifique o tipo de retorno da função. Retorne o valor (cuidado com o void)

    Tarefas

    1. Atualize a EBNF e o DS no GitHub
    2. Adicionar os novos tokens no Lexer
    3. Adicionar os novos nós vazios: FuncDec, FuncCall e Return
    4. Modificar o Parser:
    5. Adicionar parseFuncDeclaration() - irá gerar um nó FuncDec
    6. Adicionar a declaração de funções e variáveis globais no parseProgram()
    7. Modificar os métodos para a chamada de função - irá gerar um nó FuncCall
    8. Adicionar Return ao Statement - irá gerar um nó Return
    9. Alterar a SymbolTable:
    10. Modificar para uma estrutura de lista ligada reversa
    11. Alterar o getter/setter para buscar recursivamente
    12. Implementar/Alterar os Nodes:
    13. Nó Return:
      • Retornar o valor/tipo do evaluate() do único filho
    14. Nó Block:
      • Alterar o while para retornar quando o filho filho executado for um Return
      • Criar um novo objeto SymbolTable encadeado quando o nó filho a ser executado for um Block
    15. Nó FuncDec:
      • Criar uma nova variável na SymbolTable, passando o próprio nó como valor. Precisa colocar o tipo e uma sinalização que é uma função
    16. Nó VarDec:
      • Modificar sinalizar que uma variável a ser criada não é uma função
    17. Nó FuncCall:
      • Recuperar o nó da declaração da função na SymbolTable
      • Verificar se o número de argumentos está correto
      • Criar uma nova SymbolTable encadeada
      • Declarar os argumentos na nova SymbolTable e atribuir os valores da chamada, em ordem
      • Se houver return no Block, retornar o valor
    18. Nós If e While:
      • Se o filho do tipo Block retornar valor, esses nós devem retornar esse valor
    19. Run:
    20. Adicionar um nó FuncCall para main antes de retornar a AST completa.

    Atenção

    Tomar cuidado com as possíveis mensagens de erro.

    Base de Testes:

    Além do código exemplo acima que deve funcionar conforme o esperado, teste os seguintes elementos:

    • Com erros:
    • Chamar a função com número incorreto de argumentos.
    • Passar argumentos de tipos diferentes.
    • Chamar uma função que não existe.
    • Usar uma variável fora de escopo.
    • Sem erros:
    • Fazer uma função recursiva.
    • Sugira testes adicionais

    Para ganhar A+

    • Prazo: 16/Out/2025.
    • Você deve implementar a geração de código para funções (v3.1).
    • O seu compilador deve realizar todas as etapas de compilação.
    • Ele deve ser hábil suficiente para fazer chamadas recursivas.
    • Gerar um relatório explicando como foi feita a etapa e enviar por email.
    • Não há correção no servidor.
